# ТГКсборщик — полная сборка Telegram-бота

Довести бота до рабочего результата, включая оформление и эксплуатацию. Работает как обычный SKILL.md в Codex и Claude Code; наличие инструментов проверять фактически. Не превращать любой новый бот в копию Emojinator: его персонаж, каналы и функции не являются универсальными настройками.

## Начало и область

В продолжении прочитать память проекта и существующий код; не повторять полученные ответы. Для нового бота одним коротким раундом выяснить назначение, аудиторию, название/язык, основные действия, оформление, условия доступа и место запуска. Токен вводится локально в секреты, не в переписку. Уже выбранный бренд сохранить. Независимые части готовить, пока недостающие настройки уточняются.

Создать короткий список поставки в памяти проекта: функции, onboarding, управление, доступ, BotFather, хостинг, проверки. Если установлен Absolute Skill — следовать его памяти и визуальному процессу; без него вести эквивалентные записи требований/решений/проверок. Не требовать отсутствующих навыков как зависимости.

## Укомплектовать продукт

- Написать /start: что делает бот, что требуется для доступа, 2–4 действия пользователя. Эмодзи по смыслу, не вместо подписей. Бесплатность, Premium и ограничения описывать точно. /help — форматы, размеры и восстановление после ошибки.
- Подготовить короткие about/description, имя, аватар и Description Picture до первого сообщения. Читать [onboarding-media.md](references/onboarding-media.md) для файлов и способа отправки. Не путать аватар, pre-start картинку и фото после /start.
- Добавить setMyCommands и видимые кнопки реальных действий; один только список слэш-команд не заменяет кнопки. Постоянное reply-меню — основные действия, inline — текущий результат/проверка подписки/назад. Для цвета и маршрутизации читать [buttons-access.md](references/buttons-access.md).
- Если пользователь выбрал бесплатность за подписку — сделать ссылки на нужные каналы, кнопку проверки и серверную проверку каждого защищённого действия. Количество каналов задаёт проект, не обязательно два. Не объявлять включённой неподключённую проверку.
- Если бот принимает медиа — проверять реальный формат, байты, размеры, анимацию и декодирование до тяжёлой обработки; показать понятную причину отказа и исправление. Нужные лимиты выводятся из нагрузки и назначения. Для стикеров/эмодзи читать [media-bots.md](references/media-bots.md).
- Сохранить обычному пользователю только рабочие функции; служебные действия, ID и установочные изображения доступны владельцу. /help и удаление собственных временных данных не должны требовать подписку.

## Изображения в разных средах

В Codex использовать доступный imagegen для иллюстраций. В Claude Code проверить доступный генератор/коннектор, не придумывать наличие Codex imagegen. При отсутствии генератора использовать согласованное изображение пользователя либо реально подготовить авторский SVG и экспорт, если такой способ согласован. Для иллюстрации с открытым направлением подготовить brief/промпт и запросить недостающий источник; не выдавать заглушку за готовую картинку. Не подключать платный API или внешнюю передачу файлов без соответствующей авторизации. Промпт и оригинал сохранять рядом с экспортом. Движение существующего изображения можно рассчитать FFmpeg; лицо, текст и композиция не должны случайно перерисовываться.

## Хостинг

Читать [hosting.md](references/hosting.md). Сначала сравнить нагрузку и среду: Telegram Serverless для совместимого JavaScript/SDK; VPS (например Hetzner) для Python, FFmpeg, моделей и системных зависимостей. «Бесплатный бот» не означает бесплатный сервер. Актуальные тарифы, квоты и доступность подтвердить перед выбором; не фиксировать временную бесплатность навсегда. Покупка, смена production-хостинга и расширение доступа — только в рамках явной авторизации пользователя.

На выбранном хостинге подготовить секреты, сохранение данных, перезапуск, ограничение ресурсов, журналы без токена, обновление и откат. Не запускать два poller одного токена, не совмещать polling с активным webhook. Локальное окно терминала не является запуском 24/7.

## Проверить и сдать

Проверить полный сценарий с файлом, ошибкой и кнопками; затем реальный Bot API и клиент, когда доступ есть. Для gate — оба состояния подписки, ошибка API, отписка и старая кнопка. Для callback — принадлежность результата пользователю, allowlist действий и немедленный answerCallbackQuery. Для хостинга — restart, persistence, логи и ресурсы.

Стикер/эмодзи декодировать и проверить фактический экспорт, не только настройки кодека. На native UI проверить мобильное и широкое окно, подписи и касания. Недоступный просмотр обозначить точно; тестовые payload не являются скриншотом. Для description-media запустить `scripts/check_description_media.py FILE`; нужен ffprobe.

Сдать работающий проект и файлы BotFather, список реально включённых функций, способ входа и остаточные блокеры. Различать: реализовано / проверено в тестах / подключено / проверено в Telegram / запущено 24/7. Не оставлять разрешённые части только в виде плана.

## Перенос навыка

Codex: папка `tgk-sborshchik` в пользовательском каталоге skills; вызов `$tgk-sborshchik`. Claude Code: та же папка в `~/.claude/skills/` либо проектном `.claude/skills/`; вызов `/tgk-sborshchik`. Локальный личный навык не гарантирует доступность в облачной сессии — туда добавить проектный навык по правилам среды. Не копировать секреты и данные существующего бота вместе с навыком.
