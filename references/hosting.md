# Хостинг: проверять актуальные условия

Снимок исследования: 2026-10-09. Использовать как основание выбора, не как вечный тариф.

## Telegram Serverless

[Документация Telegram Serverless](https://blogfork.telegram.org/bots/serverless) описывает запуск JavaScript-модулей через tgcloud, обработчики updates, встроенную БД и раздел Serverless в BotFather. Runtime ограничен SDK и модулями проекта: без npm-пакетов и файловой системы, сеть через SDK fetch. Документация сообщает обновление 2026-10-06. На просмотренной странице нет подтверждения бесплатности, сроков или гарантированных квот; проверить их в официальных условиях/доступном интерфейсе перед обещанием «бесплатно».

Это кандидат для совместимого обработчика бота/Mini App, не место для загрузки готового Python/FFmpeg/rembg контейнера. Медиа-рендер на отдельном worker/VPS — архитектурный вывод из ограничений runtime, а не заявленная функция Telegram. Не мигрировать существующий Python-бот молча. Проверить доступ владельца к Serverless и официальное происхождение CLI/точную версию перед установкой; локально этот маршрут не исполнялся. Deploy и migration различать, изменения схемы проверять перед применением. CLI run вызывает платформу и не является полностью локальным sandbox без внешних эффектов.

## VPS / Hetzner

[Hetzner Cloud](https://www.hetzner.com/cloud/) — платные виртуальные серверы; актуальные цена, регион, архитектура, IPv4, налоги и backups уточняются в заказе. Не сохранять старую цену в инструкциях. [Billing FAQ](https://docs.hetzner.com/cloud/billing/faq/) — источник правил оплаты. Не покупать сервер без конкретного бюджета/авторизации.

Выбрать ресурсы по измерению пика памяти, времени обработки, объёма моделей и диска. Для Pillow/rembg/FFmpeg проверить поддержку архитектуры выбранных пакетов. Один контейнер с bounded очередью может быть стартовой конфигурацией, но не доказательством достаточности VPS.

Long polling обычно не требует домена/входящего публичного порта; webhook требует HTTPS, проверки secret_token и корректного приёма updates. Перед переключением остановить старый consumer и проверить getWebhookInfo. Зафиксировать service/compose, restart policy, non-root, секреты отдельно от image/repo, постоянный volume, резервирование нужной БД, лимиты CPU/RAM/очереди/диска, TTL и план отката. Сетевые логи не должны печатать URL с bot token.

После размещения проверить запуск после рестарта, реальный /start и обработку, сохранение данных, cleanup и ошибки Telegram. Остановленный ноутбук не должен выключать production-бота. Бесплатные квоты любого другого провайдера сверять отдельно; не выдавать Telegram Bot API platform за бесплатный backend-хостинг.
